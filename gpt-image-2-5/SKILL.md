# GPT Image 2.5 画像生成

OpenAI の Image API を `scripts/gpt_image.py` から呼び出して画像を作る。Python 標準ライブラリだけで動くので pip install は不要。

ワークフローは 2 段階になっている。理由は、xhigh は medium より大幅に時間とコストがかかるため、構図やアイデアを medium で安く詰めてから、確定したものだけを xhigh で仕上げるのが効率的だから。

| 段階 | 品質 | 使う場面 |
|---|---|---|
| 下書き (generate) | `medium` | 通常の画像生成依頼すべて |
| リリース (release) | `xhigh` | 「リリース用」「本番用」「最終版」「仕上げて」と言われたとき |

## 前提

- API キーは環境変数 `OPENAI_IMAGE_API_KEY` から読む。無い場合はスキルフォルダ直下の `.env`、次にスクリプトを実行したディレクトリ（プロジェクトのルートなど）の `.env` を読む（書式は `OPENAI_IMAGE_API_KEY=sk-...`）。プロジェクトの `.env` を使う場合は、そのディレクトリで実行すること。キーの値は会話に表示しないこと。ユーザーにチャットへキーを貼ってもらうのも避ける（会話履歴に残るため）。
- claude.ai で使う場合、`api.openai.com` へのネットワーク通信が許可されている必要がある。接続エラーが出たら、設定 > 機能 のネットワーク通信（ドメイン許可リスト）に `api.openai.com` を追加するよう案内する。
- スクリプトのパスはこの SKILL.md と同じフォルダの `scripts/gpt_image.py`。以下 `$SKILL` はこのスキルのフォルダを指す。

## 1. 下書きを作る（通常）

```bash
python3 $SKILL/scripts/gpt_image.py generate \
  --prompt "<英語または日本語の詳細なプロンプト>" \
  --size 1024x1024
```

- 品質は指定しなければ `medium`。ユーザーが明示的に別の品質を指定したときだけ `--quality` を変える。
- サイズ: 正方形 `1024x1024`、横長 `1536x1024`、縦長 `1024x1536`。16:9 なら `1536x864` や `1920x1088` のようなカスタム値も可（幅・高さは 16 の倍数、比率は 1:3〜3:1、長辺 3840px 以下）。用途（バナー、スマホ壁紙、サムネなど）から適切なものを選ぶ。
- 透過背景が必要なら `--background transparent`（png / webp のみ）。
- 複数案が欲しいと言われたら `--n 2` など。
- モデルは既定で `gpt-image-2.5-sunburst`（高品質・編集精度重視）。「速く」「たくさん試したい」と言われたら `--model gpt-image-2.5-flare`。
- 出力先は claude.ai では `/mnt/user-data/outputs`、それ以外ではカレントの `gpt-image-outputs/`。`--out-dir` で変更できる。
- 画像と同じ名前の `.json`（サイドカー）にプロンプト・モデル・サイズなどが保存される。リリース時にこれを使うので、画像と一緒に保管するよう伝える。

### プロンプトの書き方

ユーザーの依頼が短くても、そのまま投げずに具体化する。被写体、構図、画風（写真／イラスト／3D など）、光と色、雰囲気、画像内に入れる文字（あれば正確な文言を引用符で）を盛り込む。画像内の文字は日本語より英語のほうが崩れにくいので、日本語の文字入れを頼まれた場合は崩れる可能性があることを一言添える。

## 2. リリース用に xhigh で仕上げる

ユーザーが medium 画像をアップロードした、または直前に作った下書きを「リリース用にして」と言われたら:

```bash
python3 $SKILL/scripts/gpt_image.py release --image <medium画像のパス>
```

- 既定の `--mode edit` は、medium 画像そのものを edits API に入力し、構図・被写体・色・文字を保ったまま `xhigh` で描き直す。ユーザーが気に入った下書きを「そのまま綺麗にしたい」ケースに合っているので、基本はこれを使う。
- サイズは元画像から自動で引き継ぐ。プロンプトはサイドカー JSON から自動で読む。
- **サイドカーが無い場合**（ユーザーがチャットに画像だけアップロードした場合など）は `--prompt` が必須。画像を自分で見て内容を詳しく記述したプロンプトを作って渡す。claude.ai でアップロードされたファイルは通常 `/mnt/user-data/uploads/` にある。
- 「同じプロンプトで作り直して」と言われたときだけ `--mode regenerate`（元画像を使わずプロンプトから xhigh で再生成。構図は変わる）。
- 「max で」と明示されたら `--quality max`。

xhigh は 1 枚あたり数十秒〜数分かかることがある。実行前に「xhigh で仕上げ中です（少し時間がかかります）」と一言伝えるとよい。

## 3. 結果の返し方

スクリプトは成功時に JSON（`files`, `model`, `quality`, `size`, `elapsed_sec`, `usage`）を標準出力に出す。生成した画像ファイルをユーザーに提示し、使ったモデル・品質・サイズを短く伝える。下書きの場合は「気に入ったら『リリース用に』と言ってください」と次の一手を添える。

## エラー時

スクリプトは失敗時に `{"ok": false, "error": "..."}` を標準エラーに出して終了コード 1 を返す。

- `API key not found` → 環境変数または `.env` の設定方法を案内する。
- `Could not reach` → ネットワーク通信の許可（`api.openai.com`）を案内する。
- `OpenAI API error 400` → メッセージを読み、サイズ指定やパラメータを直して再実行する。コンテンツポリシーで拒否された場合はその旨を伝え、プロンプトの調整案を出す。
- `OpenAI API error 401/403` → キーが無効か、組織の認証（Organization verification）が必要な可能性を伝える。
- `OpenAI API error 429` → レート制限か残高不足。少し待つか、OpenAI の課金設定を確認するよう伝える。
